# Cloud Computing: Pengertian, Cara Kerja, Jenis Layanan, Manfaat, dan Tantangannya

Setiap kali Anda menyimpan foto di Google Drive, menonton film di layanan streaming, atau mengirim dokumen melalui email, Anda sedang memanfaatkan **cloud computing**. Teknologi ini bekerja di balik layar hampir semua aplikasi yang kita gunakan setiap hari. Bagi perusahaan, cloud computing telah mengubah cara membangun dan menjalankan sistem teknologi informasi. Dulu, perusahaan harus membeli server dan membangun ruang server sendiri. Kini, mereka bisa menyewa kapasitas komputasi sesuai kebutuhan hanya dalam hitungan menit.

Meski sudah sangat umum, banyak orang masih bingung tentang apa sebenarnya cloud computing itu. Istilah "cloud" atau awan sering terdengar abstrak, seolah-olah data melayang di udara. Kenyataannya, cloud computing berjalan di atas pusat data fisik yang berisi ribuan server. Artikel ini menjelaskan pengertian cloud computing, cara kerjanya, model layanan dan model penerapannya, serta manfaat dan risikonya. Kami juga membahas aspek regulasi di Indonesia, cara memilih layanan cloud, dan tips mengendalikan biaya.

## Apa Itu Cloud Computing?

Cloud computing atau komputasi awan adalah model penyediaan sumber daya komputasi melalui internet berdasarkan permintaan. Sumber daya tersebut meliputi server, penyimpanan data, basis data, jaringan, perangkat lunak, hingga layanan analitik dan kecerdasan buatan. Pengguna tidak perlu membeli dan mengelola perangkat keras sendiri. Mereka cukup menyewa sumber daya dari penyedia layanan cloud dan membayar sesuai pemakaian. Semua sumber daya tersebut dapat diakses dari mana saja selama terhubung ke internet.

Lembaga standar Amerika Serikat, NIST, merumuskan definisi cloud computing yang banyak dijadikan rujukan. Menurut definisi tersebut, cloud computing adalah model yang memungkinkan akses jaringan yang mudah dan sesuai permintaan ke kumpulan sumber daya komputasi yang dapat dikonfigurasi. Sumber daya tersebut dapat disediakan dan dilepaskan dengan cepat, dengan upaya pengelolaan yang minimal. Definisi ini menekankan tiga hal penting. Ketiganya adalah akses sesuai permintaan, kumpulan sumber daya bersama, dan kecepatan penyediaan.

Cara mudah memahami cloud computing adalah dengan analogi listrik. Dulu, beberapa pabrik membangun pembangkit listrik sendiri untuk menjalankan mesin mereka. Seiring waktu, hampir semua orang beralih menggunakan listrik dari jaringan penyedia. Mereka cukup mencolokkan perangkat dan membayar tagihan sesuai pemakaian. Cloud computing melakukan hal yang sama untuk sumber daya komputasi.

Istilah "awan" sendiri berasal dari kebiasaan para insinyur menggambar internet sebagai simbol awan dalam diagram jaringan. Simbol ini menunjukkan bagian jaringan yang rumit dan tidak perlu dirinci. Dari sudut pandang pengguna, detail infrastruktur di balik layanan cloud memang tidak perlu dipikirkan. Pengguna hanya melihat layanan yang siap pakai. Namun, di balik layar, ada pusat data besar yang bekerja tanpa henti.

## Sejarah Singkat Cloud Computing

Gagasan tentang komputasi sebagai layanan bersama sebenarnya sudah muncul sejak tahun 1960-an. Pada masa itu, komputer sangat mahal dan berukuran besar. Banyak organisasi menggunakan sistem *time-sharing*, yaitu berbagi satu komputer besar untuk banyak pengguna secara bergantian. Beberapa ilmuwan komputer saat itu sudah membayangkan bahwa komputasi suatu hari bisa disediakan seperti layanan utilitas publik. Gagasan tersebut baru benar-benar terwujud beberapa dekade kemudian.

Perkembangan teknologi virtualisasi menjadi fondasi penting bagi cloud computing modern. Virtualisasi memungkinkan satu server fisik dibagi menjadi beberapa mesin virtual yang berjalan terpisah. Dengan teknologi ini, sumber daya server dapat dimanfaatkan jauh lebih efisien. Pertumbuhan internet berkecepatan tinggi juga memungkinkan akses jarak jauh ke server dengan lancar. Kombinasi keduanya membuka jalan bagi lahirnya layanan cloud komersial.

Tonggak penting terjadi pada tahun 2006 ketika Amazon Web Services meluncurkan layanan penyimpanan S3 dan layanan server virtual EC2 untuk umum. Untuk pertama kalinya, pengembang bisa menyewa server dan penyimpanan dengan kartu kredit dan membayar per jam. Beberapa tahun kemudian, Google dan Microsoft ikut meluncurkan platform cloud mereka. Sejak itu, pasar cloud tumbuh sangat pesat dan menjadi bagian inti dari industri teknologi. Kini, cloud computing digunakan oleh perusahaan rintisan hingga lembaga pemerintahan.

## Bagaimana Cloud Computing Bekerja?

Di balik kesederhanaan layanan cloud, ada infrastruktur yang sangat kompleks. Penyedia cloud membangun pusat data berskala besar di berbagai wilayah di dunia. Setiap pusat data berisi ribuan server, perangkat penyimpanan, dan perangkat jaringan. Pusat data tersebut dilengkapi sistem listrik cadangan, pendingin, dan keamanan fisik yang ketat. Semua komponen ini dikelola oleh perangkat lunak yang memungkinkan pengguna mengaksesnya dari jarak jauh.

### Pusat Data, Region, dan Zona Ketersediaan

Penyedia cloud biasanya membagi infrastrukturnya ke dalam beberapa *region*. Region adalah wilayah geografis tertentu, misalnya Jakarta, Singapura, atau Tokyo. Setiap region terdiri dari beberapa zona ketersediaan yang terpisah secara fisik. Zona-zona ini memiliki sumber listrik dan jaringan yang independen. Tujuannya agar gangguan di satu zona tidak melumpuhkan seluruh region.

Pengguna dapat memilih region yang paling dekat dengan pelanggannya untuk mengurangi latensi. Pemilihan region juga berkaitan dengan aturan tentang lokasi penyimpanan data. Beberapa penyedia cloud global telah membuka region di Indonesia. Hal ini memudahkan perusahaan Indonesia yang membutuhkan data tersimpan di dalam negeri. Untuk sistem yang sangat penting, aplikasi bisa dijalankan di beberapa zona sekaligus agar tetap berjalan ketika satu zona bermasalah.

### Virtualisasi

Virtualisasi adalah teknologi inti yang memungkinkan cloud computing bekerja secara efisien. Perangkat lunak bernama *hypervisor* membagi satu server fisik menjadi beberapa mesin virtual. Setiap mesin virtual memiliki sistem operasi, prosesor virtual, memori, dan penyimpanan sendiri. Bagi pengguna, mesin virtual terasa seperti server fisik yang terpisah. Padahal, banyak mesin virtual sebenarnya berbagi perangkat keras yang sama.

Dengan virtualisasi, penyedia cloud dapat memanfaatkan perangkat kerasnya secara optimal. Server yang biasanya menganggur sebagian waktu kini bisa melayani banyak pelanggan sekaligus. Mesin virtual juga bisa dibuat, dipindahkan, atau dihapus dengan cepat melalui perangkat lunak. Fleksibilitas inilah yang memungkinkan pengguna menambah atau mengurangi server dalam hitungan menit. Tanpa virtualisasi, model bisnis cloud seperti sekarang hampir tidak mungkin terwujud.

### Kontainer dan Orkestrasi

Selain mesin virtual, cloud modern juga banyak menggunakan teknologi kontainer. Kontainer membungkus aplikasi beserta semua dependensinya ke dalam satu paket yang ringan. Berbeda dengan mesin virtual, kontainer berbagi kernel sistem operasi dengan host. Karena itu, kontainer bisa dijalankan lebih cepat dan lebih hemat sumber daya. Docker adalah salah satu teknologi kontainer yang paling dikenal.

Ketika jumlah kontainer mencapai puluhan hingga ribuan, pengelolaannya membutuhkan sistem orkestrasi. Kubernetes adalah platform orkestrasi kontainer yang paling banyak digunakan saat ini. Platform ini mengatur penempatan kontainer, menyeimbangkan beban, dan memulihkan kontainer yang gagal secara otomatis. Hampir semua penyedia cloud besar menawarkan layanan Kubernetes yang dikelola. Dengan layanan ini, tim pengembang dapat fokus pada aplikasi tanpa repot mengelola klaster sendiri.

### Akses Melalui Konsol, API, dan Infrastructure as Code

Pengguna mengakses sumber daya cloud melalui beberapa cara. Cara paling sederhana adalah melalui konsol web yang menyediakan antarmuka grafis. Cara lain adalah melalui antarmuka baris perintah dan API yang memungkinkan otomatisasi. Hampir semua tindakan di cloud, seperti membuat server atau mengatur jaringan, bisa dilakukan melalui API. Kemampuan ini menjadi dasar dari praktik otomatisasi infrastruktur.

Praktik *Infrastructure as Code* memungkinkan infrastruktur didefinisikan dalam bentuk kode. Alat seperti Terraform atau alat bawaan penyedia cloud membaca kode tersebut dan membuat sumber daya sesuai definisi. Pendekatan ini membuat infrastruktur dapat direplikasi, ditinjau, dan dilacak perubahannya seperti kode aplikasi. Kesalahan konfigurasi manual juga dapat dikurangi. Bagi tim yang mengelola banyak lingkungan, praktik ini sangat menghemat waktu.

## Lima Karakteristik Utama Cloud Computing

Definisi NIST menyebutkan lima karakteristik penting yang membedakan cloud computing dari hosting tradisional. Karakteristik ini menjadi acuan untuk menilai apakah suatu layanan benar-benar bersifat cloud. Tidak semua layanan yang menyebut dirinya cloud memenuhi kelima karakteristik ini secara penuh. Memahaminya akan membantu Anda mengevaluasi penawaran dari penyedia layanan. Berikut penjelasan kelima karakteristik tersebut.

**1. Layanan mandiri sesuai permintaan.** Pengguna dapat menyediakan sumber daya seperti server atau penyimpanan secara mandiri kapan saja. Proses ini tidak memerlukan interaksi dengan petugas penyedia layanan. Cukup beberapa klik di konsol atau satu perintah melalui API, sumber daya langsung tersedia. Bandingkan dengan cara tradisional yang memerlukan pemesanan, pengiriman, dan pemasangan server fisik. Proses yang dulu memakan waktu berminggu-minggu kini bisa selesai dalam hitungan menit.

**2. Akses jaringan yang luas.** Layanan cloud dapat diakses melalui jaringan menggunakan berbagai jenis perangkat. Pengguna bisa mengaksesnya dari laptop, ponsel, tablet, atau server lain. Akses ini menggunakan protokol standar sehingga tidak bergantung pada perangkat tertentu. Karakteristik ini memungkinkan kerja jarak jauh dan kolaborasi lintas lokasi. Selama ada koneksi internet, layanan dapat digunakan dari mana saja.

**3. Pengumpulan sumber daya.** Penyedia cloud mengumpulkan sumber daya komputasi untuk melayani banyak pelanggan sekaligus. Sumber daya fisik dan virtual dialokasikan secara dinamis sesuai permintaan setiap pelanggan. Model ini disebut *multi-tenant*. Pelanggan umumnya tidak mengetahui lokasi persis perangkat keras yang mereka gunakan. Namun, mereka biasanya bisa memilih lokasi pada tingkat yang lebih umum, seperti negara atau region.

**4. Elastisitas yang cepat.** Sumber daya dapat ditambah atau dikurangi dengan cepat sesuai kebutuhan, bahkan secara otomatis. Toko daring, misalnya, bisa menambah server menjelang promo besar dan menguranginya setelah promo selesai. Bagi pengguna, kapasitas cloud terasa seolah tidak terbatas. Elastisitas ini mencegah dua masalah sekaligus. Masalah pertama adalah kekurangan kapasitas saat trafik melonjak, dan masalah kedua adalah pemborosan saat trafik sepi.

**5. Layanan yang terukur.** Penggunaan sumber daya cloud diukur secara otomatis. Pengukuran ini mencakup waktu pemakaian server, jumlah penyimpanan, atau jumlah data yang ditransfer. Pengguna dan penyedia dapat memantau pemakaian tersebut secara transparan. Data pengukuran ini menjadi dasar penagihan dengan model bayar sesuai pemakaian. Pengguna juga bisa memanfaatkan data ini untuk mengoptimalkan biaya.

## Model Layanan: IaaS, PaaS, SaaS, dan Serverless

Layanan cloud umumnya dibagi menjadi beberapa model berdasarkan tingkat pengelolaan yang ditangani penyedia. Semakin tinggi tingkat layanannya, semakin sedikit hal yang perlu dikelola pengguna. Namun, kendali pengguna atas detail teknis juga semakin berkurang. Memahami perbedaan setiap model membantu Anda memilih layanan yang sesuai. Berikut penjelasan model-model layanan utama.

### Infrastructure as a Service (IaaS)

IaaS menyediakan sumber daya infrastruktur dasar, seperti server virtual, penyimpanan, dan jaringan. Pengguna bertanggung jawab mengelola sistem operasi, perangkat lunak pendukung, aplikasi, dan data. Penyedia cloud bertanggung jawab atas perangkat keras fisik, pusat data, dan lapisan virtualisasi. Model ini memberikan kendali paling besar kepada pengguna di antara model layanan cloud lainnya. IaaS cocok untuk organisasi yang membutuhkan fleksibilitas tinggi dan memiliki tim teknis yang memadai.

Contoh layanan IaaS antara lain Amazon EC2, Google Compute Engine, dan Azure Virtual Machines. Layanan VPS yang ditawarkan banyak penyedia hosting juga memiliki karakter mirip IaaS. Pengguna IaaS biasanya memindahkan aplikasi dari server fisik ke server virtual tanpa banyak perubahan. Pendekatan ini sering menjadi langkah awal migrasi ke cloud. Seiring waktu, aplikasi bisa dioptimalkan untuk memanfaatkan layanan cloud lain.

### Platform as a Service (PaaS)

PaaS menyediakan platform siap pakai untuk mengembangkan dan menjalankan aplikasi. Penyedia mengelola infrastruktur, sistem operasi, dan lingkungan runtime. Pengguna cukup fokus pada kode aplikasi dan data. Pengembang tidak perlu memikirkan pembaruan sistem operasi atau konfigurasi server web. Model ini mempercepat proses pengembangan dan penerapan aplikasi.

Contoh PaaS antara lain Google App Engine, Azure App Service, dan Heroku. Layanan basis data terkelola, seperti Amazon RDS atau Cloud SQL, juga sering digolongkan sebagai PaaS. Platform penerapan untuk aplikasi web modern, seperti Vercel dan Netlify, memiliki karakter serupa. PaaS sangat cocok untuk tim pengembang kecil yang ingin bergerak cepat. Kekurangannya, pengguna harus mengikuti batasan dan cara kerja platform yang dipilih.

### Software as a Service (SaaS)

SaaS adalah perangkat lunak siap pakai yang diakses melalui internet, biasanya lewat browser atau aplikasi. Penyedia mengelola seluruh komponen, mulai dari infrastruktur hingga aplikasi itu sendiri. Pengguna cukup mendaftar, masuk, dan menggunakan layanan. Pembaruan dan perbaikan dilakukan oleh penyedia tanpa perlu instalasi di sisi pengguna. Model ini adalah bentuk cloud computing yang paling akrab bagi masyarakat umum.

Contoh SaaS sangat banyak, seperti Gmail, Google Workspace, Microsoft 365, Zoom, Canva, dan berbagai aplikasi akuntansi daring. Banyak bisnis di Indonesia menggunakan SaaS untuk kasir, penggajian, manajemen proyek, dan layanan pelanggan. Biaya SaaS biasanya berupa langganan bulanan atau tahunan per pengguna. Model ini sangat cocok untuk UMKM karena tidak memerlukan tim teknis. Hal yang perlu diperhatikan adalah keamanan akun dan kepemilikan data.

### Serverless dan Function as a Service (FaaS)

Serverless adalah model di mana pengembang menjalankan kode tanpa mengelola server sama sekali. Istilah serverless bukan berarti tidak ada server. Server tetap ada, tetapi sepenuhnya dikelola oleh penyedia dan tidak terlihat oleh pengembang. Pada model *Function as a Service*, kode ditulis dalam bentuk fungsi kecil yang dijalankan saat ada pemicu tertentu. Pemicu tersebut bisa berupa permintaan HTTP, unggahan file, atau pesan dari antrean.

Contoh layanan serverless adalah AWS Lambda, Google Cloud Functions, dan Azure Functions. Biaya serverless dihitung berdasarkan jumlah eksekusi dan durasi pemrosesan. Jika tidak ada permintaan, biayanya bisa mendekati nol. Model ini cocok untuk beban kerja yang tidak menentu atau berbasis peristiwa. Tantangannya meliputi waktu mulai awal (*cold start*), batas durasi eksekusi, dan kesulitan dalam pengujian lokal.

### Perbandingan Model Layanan

| Komponen | On-Premise | IaaS | PaaS | SaaS |
|---|---|---|---|---|
| Aplikasi | Pengguna | Pengguna | Pengguna | Penyedia |
| Data | Pengguna | Pengguna | Pengguna | Pengguna (penyimpanan oleh penyedia) |
| Runtime dan middleware | Pengguna | Pengguna | Penyedia | Penyedia |
| Sistem operasi | Pengguna | Pengguna | Penyedia | Penyedia |
| Virtualisasi dan server | Pengguna | Penyedia | Penyedia | Penyedia |
| Jaringan dan pusat data | Pengguna | Penyedia | Penyedia | Penyedia |

Tabel di atas menunjukkan pembagian pengelolaan secara umum. Pembagian sebenarnya bisa sedikit berbeda tergantung layanan dan penyedia. Satu hal yang tidak pernah berpindah adalah tanggung jawab pengguna atas data dan akses akunnya sendiri. Bahkan pada SaaS, pengguna tetap bertanggung jawab mengatur siapa yang boleh mengakses data. Konsep ini akan dibahas lebih lanjut di bagian model tanggung jawab bersama.

## Model Penerapan: Public, Private, Hybrid, dan Multi-Cloud

Selain berdasarkan jenis layanan, cloud computing juga dibedakan berdasarkan model penerapannya. Model penerapan menjelaskan siapa yang memiliki infrastruktur dan siapa saja yang bisa menggunakannya. Pilihan model penerapan berkaitan erat dengan kebutuhan keamanan, kepatuhan, dan biaya. Tidak ada model yang paling baik untuk semua organisasi. Berikut penjelasan setiap model.

### Public Cloud

Public cloud adalah infrastruktur cloud yang dimiliki dan dioperasikan oleh penyedia layanan, lalu disewakan kepada publik. Banyak pelanggan berbagi infrastruktur yang sama, meskipun data dan sumber daya mereka dipisahkan secara logis. Contoh penyedia public cloud global adalah Amazon Web Services, Microsoft Azure, dan Google Cloud. Ada juga penyedia lain seperti Alibaba Cloud dan Huawei Cloud, serta sejumlah penyedia cloud lokal di Indonesia. Public cloud adalah model yang paling banyak digunakan karena mudah diakses dan tidak membutuhkan investasi awal yang besar.

Kelebihan public cloud adalah skalabilitas yang hampir tidak terbatas dan pilihan layanan yang sangat luas. Pengguna bisa memanfaatkan layanan canggih seperti analitik data dan kecerdasan buatan tanpa membangunnya sendiri. Biaya dibayar sesuai pemakaian tanpa perlu membeli perangkat keras. Kekurangannya, pengguna memiliki kendali terbatas atas infrastruktur fisik. Beberapa organisasi juga memiliki kekhawatiran tentang kepatuhan regulasi dan lokasi data.

### Private Cloud

Private cloud adalah infrastruktur cloud yang digunakan secara eksklusif oleh satu organisasi. Infrastruktur ini bisa berada di pusat data milik organisasi sendiri atau dikelola oleh pihak ketiga. Private cloud tetap menerapkan prinsip cloud seperti layanan mandiri, virtualisasi, dan elastisitas. Perbedaannya, sumber daya tidak dibagi dengan organisasi lain. Model ini memberi kendali dan isolasi yang lebih besar.

Private cloud sering dipilih oleh lembaga keuangan, instansi pemerintah, dan perusahaan dengan data yang sangat sensitif. Organisasi tersebut biasanya memiliki aturan ketat tentang lokasi dan pengelolaan data. Kekurangan private cloud adalah biaya investasi dan pengelolaan yang tinggi. Organisasi harus menyediakan perangkat keras dan tim ahli untuk mengelolanya. Kapasitasnya juga terbatas pada infrastruktur yang dimiliki.

### Hybrid Cloud

Hybrid cloud menggabungkan public cloud dengan private cloud atau infrastruktur lokal. Kedua lingkungan terhubung sehingga data dan aplikasi dapat berpindah di antara keduanya. Organisasi bisa menyimpan data sensitif di private cloud, sementara aplikasi yang membutuhkan skalabilitas dijalankan di public cloud. Model ini memberikan fleksibilitas untuk menempatkan setiap beban kerja di lingkungan yang paling sesuai. Banyak perusahaan besar memilih model ini sebagai jalan tengah.

Salah satu pola penggunaan hybrid cloud adalah *cloud bursting*. Pada pola ini, aplikasi berjalan di infrastruktur lokal dalam kondisi normal. Ketika permintaan melonjak, sebagian beban dialihkan ke public cloud. Cara ini menghemat biaya infrastruktur lokal tanpa mengorbankan kemampuan menangani lonjakan. Tantangan hybrid cloud adalah kerumitan dalam mengelola dua lingkungan yang berbeda secara konsisten.

### Multi-Cloud

Multi-cloud adalah penggunaan layanan dari lebih dari satu penyedia public cloud. Sebuah perusahaan mungkin menggunakan satu penyedia untuk infrastruktur utama dan penyedia lain untuk analitik data. Alasan memilih multi-cloud antara lain untuk menghindari ketergantungan pada satu penyedia. Alasan lain adalah memanfaatkan layanan unggulan dari masing-masing penyedia. Ada juga organisasi yang menggunakan multi-cloud untuk meningkatkan ketahanan sistem.

Namun, multi-cloud juga menambah kerumitan. Setiap penyedia memiliki antarmuka, layanan, dan model keamanan yang berbeda. Tim perlu menguasai beberapa platform sekaligus. Biaya transfer data antarpenyedia juga bisa cukup besar. Karena itu, multi-cloud sebaiknya dipilih berdasarkan kebutuhan yang jelas, bukan sekadar mengikuti tren.

## Contoh Cloud Computing dalam Kehidupan Sehari-hari

Cloud computing sudah menjadi bagian dari keseharian kita, sering kali tanpa disadari. Hampir setiap aplikasi di ponsel terhubung ke layanan cloud. Berikut beberapa contoh penggunaan cloud computing yang paling umum. Contoh-contoh ini menunjukkan betapa luasnya peran cloud dalam kehidupan digital. Banyak di antaranya kita gunakan setiap hari.

**Penyimpanan dan pencadangan file.** Layanan seperti Google Drive, OneDrive, iCloud, dan Dropbox menyimpan file di server cloud. Foto dari ponsel bisa dicadangkan secara otomatis. Jika ponsel hilang atau rusak, foto tetap aman dan bisa dipulihkan di perangkat baru. File juga bisa diakses dari komputer lain kapan saja. Layanan ini sangat membantu untuk berbagi file dengan rekan kerja atau keluarga.

**Email dan aplikasi perkantoran.** Gmail, Outlook, Google Docs, dan Microsoft 365 adalah contoh aplikasi SaaS. Dokumen bisa disunting bersama secara langsung oleh banyak orang. Perubahan tersimpan otomatis tanpa perlu menekan tombol simpan. Tidak ada lagi kebingungan karena banyak versi dokumen yang dikirim bolak-balik. Kolaborasi jarak jauh menjadi jauh lebih mudah.

**Streaming video dan musik.** Layanan streaming film dan musik menyimpan katalog kontennya di infrastruktur cloud dan CDN. Ketika Anda menekan tombol putar, konten dikirim dari server terdekat. Kualitas video bisa menyesuaikan kecepatan internet secara otomatis. Semua ini memerlukan infrastruktur yang sangat besar dan elastis. Cloud computing memungkinkan layanan tersebut melayani jutaan pengguna secara bersamaan.

**Aplikasi belanja, transportasi, dan keuangan.** Aplikasi belanja daring, ojek daring, dan dompet digital berjalan di atas infrastruktur cloud. Pada momen promo besar, jumlah pengguna bisa melonjak berkali-kali lipat dalam waktu singkat. Elastisitas cloud memungkinkan aplikasi menambah kapasitas sesuai lonjakan tersebut. Setelah promo selesai, kapasitas bisa dikurangi kembali. Tanpa cloud, perusahaan harus membeli server dalam jumlah besar yang sebagian besar waktu menganggur.

**Asisten AI dan layanan pintar.** Asisten AI, penerjemah otomatis, dan fitur pengenalan suara umumnya diproses di cloud. Model AI yang besar membutuhkan daya komputasi yang tidak mungkin dimuat di ponsel biasa. Ponsel mengirim permintaan ke cloud, lalu menerima hasil pemrosesan. Hubungan erat antara cloud dan AI dibahas juga di artikel kecerdasan buatan. Perangkat rumah pintar juga sering terhubung ke cloud untuk pemrosesan dan kendali jarak jauh, seperti dijelaskan dalam artikel Internet of Things.

**Website dan aplikasi bisnis.** Banyak website, mulai dari blog pribadi hingga toko daring besar, di-*hosting* di infrastruktur cloud. Perusahaan juga menjalankan sistem internal, seperti sistem keuangan dan sumber daya manusia, di cloud. Perusahaan rintisan hampir selalu memulai bisnis mereka di cloud. Mereka bisa meluncurkan produk tanpa investasi awal yang besar untuk infrastruktur. Jika produknya berhasil, infrastruktur dapat diperbesar dengan cepat.

## Manfaat Cloud Computing

Cloud computing menawarkan banyak manfaat bagi individu, bisnis, dan organisasi. Manfaat ini menjadi alasan utama mengapa adopsi cloud terus meningkat di seluruh dunia. Namun, manfaat tersebut hanya bisa diraih jika cloud digunakan dengan perencanaan yang baik. Penggunaan yang asal-asalan justru bisa menimbulkan biaya dan risiko baru. Berikut manfaat utama cloud computing.

**1. Mengubah belanja modal menjadi biaya operasional.** Dengan cloud, organisasi tidak perlu membeli server dan membangun ruang server di awal. Biaya investasi besar diganti dengan biaya pemakaian yang dibayar secara berkala. Model ini sangat membantu perusahaan rintisan dan UMKM yang modalnya terbatas. Anggaran bisa dialokasikan untuk pengembangan produk dan pemasaran. Risiko membeli perangkat keras yang ternyata tidak terpakai juga berkurang.

**2. Skalabilitas dan elastisitas.** Kapasitas dapat ditambah atau dikurangi sesuai kebutuhan. Bisnis tidak perlu menebak kebutuhan kapasitas bertahun-tahun ke depan. Saat bisnis tumbuh, infrastruktur bisa tumbuh bersama. Saat ada lonjakan trafik musiman, kapasitas bisa ditambah sementara. Fleksibilitas ini sulit dicapai dengan infrastruktur tradisional.

**3. Kecepatan dan kelincahan.** Sumber daya baru bisa disediakan dalam hitungan menit. Tim pengembang dapat bereksperimen dengan ide baru tanpa menunggu pengadaan perangkat keras. Jika eksperimen gagal, sumber daya bisa dihapus dan biayanya berhenti. Kecepatan ini mendorong inovasi. Produk dapat diluncurkan ke pasar lebih cepat.

**4. Akses dari mana saja dan kolaborasi.** Layanan cloud dapat diakses dari berbagai lokasi dan perangkat. Karyawan bisa bekerja dari rumah, kantor cabang, atau saat bepergian. Tim di kota yang berbeda bisa bekerja pada dokumen dan sistem yang sama secara bersamaan. Model kerja hibrida menjadi lebih mudah diterapkan. Hal ini juga membuka peluang merekrut talenta dari berbagai daerah.

**5. Ketahanan dan pemulihan bencana.** Penyedia cloud menyediakan infrastruktur yang tersebar di banyak lokasi. Data dapat dicadangkan dan direplikasi ke lokasi lain secara otomatis. Jika terjadi gangguan di satu lokasi, sistem bisa dipulihkan dari lokasi lain. Membangun kemampuan serupa secara mandiri sangat mahal. Bagi negara rawan bencana seperti Indonesia, kemampuan ini sangat berharga.

**6. Akses ke teknologi canggih.** Penyedia cloud menawarkan layanan analitik data, pembelajaran mesin, dan kecerdasan buatan yang siap digunakan. Organisasi kecil pun bisa memanfaatkan teknologi yang sebelumnya hanya dimiliki perusahaan besar. Mereka tidak perlu membangun infrastruktur atau melatih model dari nol. Cukup menggunakan layanan yang tersedia melalui API. Hal ini menurunkan hambatan untuk berinovasi.

**7. Pembaruan dan pemeliharaan otomatis.** Pada layanan PaaS dan SaaS, penyedia menangani pembaruan sistem dan perangkat lunak. Pengguna selalu mendapatkan versi terbaru tanpa perlu instalasi manual. Celah keamanan pada lapisan yang dikelola penyedia juga ditambal oleh penyedia. Tim teknis internal bisa fokus pada pekerjaan yang lebih strategis. Beban pemeliharaan rutin berkurang secara signifikan.

**8. Efisiensi energi pada skala besar.** Pusat data cloud berskala besar umumnya dirancang dengan efisiensi energi yang tinggi. Pemanfaatan server juga lebih optimal dibanding ruang server kecil milik perusahaan. Banyak penyedia cloud juga berinvestasi pada energi terbarukan. Dengan memindahkan beban kerja ke cloud, organisasi berpotensi mengurangi jejak karbon. Namun, manfaat ini tetap bergantung pada cara organisasi menggunakan sumber daya cloud.

## Risiko dan Tantangan Cloud Computing

Di balik manfaatnya, cloud computing juga membawa sejumlah risiko dan tantangan. Banyak organisasi baru menyadari tantangan ini setelah bermigrasi. Mengetahuinya sejak awal membantu Anda menyusun strategi mitigasi yang tepat. Risiko-risiko ini bukan alasan untuk menghindari cloud. Risiko tersebut adalah hal yang perlu dikelola dengan sadar.

**1. Ketergantungan pada koneksi internet.** Layanan cloud membutuhkan koneksi internet yang stabil. Jika koneksi terputus, akses ke aplikasi dan data bisa terganggu. Hal ini menjadi tantangan di daerah dengan infrastruktur internet yang belum merata. Organisasi perlu menyiapkan koneksi cadangan untuk operasi yang kritis. Beberapa aplikasi juga menyediakan mode luring untuk mengurangi dampak gangguan.

**2. Biaya yang sulit dikendalikan.** Model bayar sesuai pemakaian bisa menjadi pedang bermata dua. Tanpa pengawasan, biaya cloud dapat membengkak secara tidak terduga. Penyebabnya bisa berupa server yang lupa dimatikan, penyimpanan data yang terus menumpuk, atau biaya transfer data yang tinggi. Banyak organisasi terkejut melihat tagihan bulanan yang jauh melebihi perkiraan. Pengendalian biaya dibahas lebih rinci di bagian tersendiri di bawah.

**3. Ketergantungan pada penyedia.** Setelah menggunakan banyak layanan khas dari satu penyedia, berpindah ke penyedia lain bisa sangat sulit. Kondisi ini dikenal sebagai *vendor lock-in*. Aplikasi mungkin harus ditulis ulang agar bisa berjalan di platform lain. Biaya memindahkan data dalam jumlah besar juga bisa tinggi. Penggunaan teknologi terbuka seperti kontainer dan Kubernetes dapat mengurangi risiko ini.

**4. Keamanan dan kesalahan konfigurasi.** Penyedia cloud besar umumnya memiliki keamanan infrastruktur yang sangat baik. Namun, banyak insiden kebocoran data di cloud justru disebabkan oleh kesalahan konfigurasi dari sisi pengguna. Contohnya adalah penyimpanan data yang dibiarkan terbuka untuk publik atau kata sandi yang lemah. Akun dengan hak akses berlebihan juga menjadi celah yang sering dimanfaatkan penyerang. Pembahasan tentang praktik keamanan yang baik bisa dibaca di artikel keamanan siber.

**5. Kepatuhan dan kedaulatan data.** Beberapa jenis data memiliki aturan khusus tentang lokasi penyimpanan dan cara pengelolaannya. Sektor keuangan, kesehatan, dan pemerintahan biasanya memiliki aturan yang lebih ketat. Organisasi harus memastikan penyedia cloud yang dipilih dapat memenuhi aturan tersebut. Pertanyaan tentang di mana data disimpan dan siapa yang dapat mengaksesnya menjadi sangat penting. Aspek regulasi di Indonesia dibahas di bagian berikutnya.

**6. Gangguan di sisi penyedia.** Meskipun jarang, penyedia cloud besar juga bisa mengalami gangguan layanan. Gangguan di satu region bisa memengaruhi banyak pelanggan sekaligus. Organisasi yang semua sistemnya bergantung pada satu region akan ikut terdampak. Rancang arsitektur yang tahan gangguan dengan memanfaatkan beberapa zona ketersediaan. Untuk sistem yang sangat kritis, pertimbangkan cadangan di region lain.

**7. Kekurangan keahlian.** Mengelola lingkungan cloud dengan baik membutuhkan keahlian khusus. Banyak organisasi kesulitan menemukan tenaga ahli cloud yang berpengalaman. Tanpa keahlian yang memadai, risiko kesalahan konfigurasi dan pemborosan biaya meningkat. Investasi pada pelatihan tim internal sangat dianjurkan. Bekerja sama dengan mitra yang berpengalaman juga bisa menjadi solusi.

## Model Tanggung Jawab Bersama

Salah satu konsep terpenting dalam keamanan cloud adalah model tanggung jawab bersama atau *shared responsibility model*. Konsep ini menjelaskan pembagian tanggung jawab keamanan antara penyedia cloud dan pengguna. Banyak pengguna salah mengira bahwa semua aspek keamanan menjadi tanggung jawab penyedia. Anggapan ini berbahaya dan sering menjadi penyebab insiden. Memahami pembagian tanggung jawab membantu Anda mengetahui apa yang harus Anda amankan sendiri.

Secara umum, penyedia cloud bertanggung jawab atas keamanan "dari" cloud. Ini mencakup keamanan fisik pusat data, perangkat keras, jaringan inti, dan lapisan virtualisasi. Pengguna bertanggung jawab atas keamanan "di dalam" cloud. Ini mencakup data, identitas dan hak akses pengguna, konfigurasi layanan, serta aplikasi yang dijalankan. Batas pembagian ini bergeser tergantung model layanan yang digunakan.

Pada IaaS, pengguna bertanggung jawab atas sistem operasi, pembaruan keamanan, firewall, dan aplikasi. Pada PaaS, penyedia menangani sistem operasi dan runtime, sedangkan pengguna tetap bertanggung jawab atas kode aplikasi dan konfigurasinya. Pada SaaS, penyedia menangani hampir seluruh lapisan teknis. Namun, pengguna tetap bertanggung jawab atas pengaturan akun, kata sandi, autentikasi dua faktor, dan pengaturan berbagi data. Di semua model, data dan pengelolaan akses selalu menjadi tanggung jawab pengguna.

Beberapa praktik dasar dapat membantu Anda memenuhi bagian tanggung jawab tersebut. Terapkan prinsip hak akses minimum, yaitu setiap akun hanya diberi akses yang benar-benar dibutuhkan. Aktifkan autentikasi multifaktor untuk semua akun, terutama akun dengan hak administrator. Enkripsi data sensitif, baik saat disimpan maupun saat dikirim. Aktifkan pencatatan aktivitas dan pantau aktivitas yang mencurigakan secara rutin.

## Cloud Computing dan Regulasi di Indonesia

Penggunaan cloud computing di Indonesia perlu memperhatikan sejumlah aturan yang berlaku. Aturan ini terutama berkaitan dengan perlindungan data dan lokasi penyimpanan data. Kepatuhan terhadap regulasi bukan hanya kewajiban hukum, tetapi juga bagian dari membangun kepercayaan pelanggan. Berikut beberapa regulasi utama yang relevan. Untuk kebutuhan spesifik, konsultasikan dengan ahli hukum yang memahami bidang ini.

**Peraturan Pemerintah Nomor 71 Tahun 2019.** Peraturan ini mengatur Penyelenggaraan Sistem dan Transaksi Elektronik. Di dalamnya terdapat pembedaan antara penyelenggara sistem elektronik lingkup publik dan lingkup privat. Penyelenggara lingkup publik, seperti instansi pemerintah, pada prinsipnya wajib mengelola dan menyimpan data di wilayah Indonesia, kecuali teknologi yang dibutuhkan tidak tersedia di dalam negeri. Penyelenggara lingkup privat diberi keleluasaan lebih besar mengenai lokasi penyimpanan data. Namun, mereka tetap wajib memastikan efektivitas pengawasan oleh otoritas yang berwenang.

**Undang-Undang Nomor 27 Tahun 2022 tentang Pelindungan Data Pribadi.** Undang-undang ini mengatur kewajiban pihak yang memproses data pribadi. Organisasi wajib memiliki dasar pemrosesan yang sah dan menjaga keamanan data pribadi. Undang-undang ini juga mengatur transfer data pribadi ke luar wilayah Indonesia dengan syarat tertentu. Jika menggunakan layanan cloud, organisasi tetap bertanggung jawab atas data pribadi yang disimpan di sana. Karena itu, pemilihan penyedia dan pengaturan kontrak harus memperhatikan ketentuan undang-undang ini.

**Aturan sektoral.** Beberapa sektor memiliki aturan tambahan yang lebih spesifik. Sektor jasa keuangan, misalnya, memiliki ketentuan dari Otoritas Jasa Keuangan terkait manajemen risiko teknologi informasi. Ketentuan tersebut dapat mencakup persyaratan lokasi pusat data dan pengelolaan pihak ketiga. Sektor kesehatan juga memiliki aturan terkait rekam medis elektronik. Pastikan Anda memahami aturan yang berlaku di sektor Anda sebelum memindahkan sistem ke cloud.

Kehadiran region cloud dari beberapa penyedia global di Indonesia membantu organisasi memenuhi kebutuhan penyimpanan data di dalam negeri. Penyedia cloud lokal juga menawarkan layanan dengan pusat data di Indonesia. Pilihan yang semakin beragam ini memudahkan organisasi menyeimbangkan kebutuhan kepatuhan, kinerja, dan biaya. Saat memilih penyedia, tanyakan lokasi pusat data, sertifikasi keamanan, dan dukungan kepatuhan yang mereka miliki. Dokumentasikan keputusan tersebut sebagai bagian dari tata kelola data organisasi.

## Cara Memilih Layanan Cloud

Memilih layanan cloud adalah keputusan penting yang berdampak jangka panjang. Pilihan yang tepat akan mendukung pertumbuhan bisnis dengan biaya yang wajar. Pilihan yang keliru bisa menimbulkan biaya tinggi dan kesulitan saat ingin berpindah. Berikut beberapa pertimbangan yang perlu diperhatikan. Gunakan pertimbangan ini sebagai daftar periksa saat membandingkan penyedia.

**Kebutuhan dan beban kerja.** Mulailah dengan memahami apa yang ingin dijalankan di cloud. Apakah website sederhana, aplikasi web dengan basis data, sistem analitik, atau model AI? Setiap jenis beban kerja membutuhkan layanan yang berbeda. Untuk kebutuhan sederhana, layanan PaaS atau SaaS mungkin sudah cukup. Untuk kebutuhan yang kompleks, IaaS atau kombinasi beberapa layanan mungkin diperlukan.

**Lokasi pusat data dan latensi.** Pilih penyedia yang memiliki pusat data dekat dengan mayoritas pengguna Anda. Untuk pengguna di Indonesia, pusat data di Jakarta atau Singapura umumnya memberikan latensi yang rendah. Lokasi juga penting untuk memenuhi aturan penyimpanan data. Periksa apakah layanan yang Anda butuhkan tersedia di region tersebut. Tidak semua layanan tersedia di semua region.

**Keamanan dan sertifikasi.** Periksa sertifikasi keamanan yang dimiliki penyedia, seperti ISO 27001. Pelajari fitur keamanan yang ditawarkan, seperti enkripsi, pengelolaan identitas, dan pemantauan. Tanyakan juga kebijakan penyedia tentang akses terhadap data pelanggan. Pastikan penyedia menyediakan dokumentasi yang jelas tentang model tanggung jawab bersama. Keamanan yang baik adalah syarat mutlak, bukan fitur tambahan.

**Biaya dan model penagihan.** Pelajari struktur harga setiap layanan dengan teliti. Selain biaya server dan penyimpanan, perhatikan biaya transfer data keluar, biaya permintaan API, dan biaya dukungan teknis. Gunakan kalkulator harga dari penyedia untuk memperkirakan biaya bulanan. Bandingkan juga opsi diskon untuk komitmen jangka panjang. Pastikan ada fitur peringatan anggaran agar biaya tidak membengkak tanpa disadari.

**Dukungan teknis dan ekosistem.** Periksa jenis dukungan teknis yang tersedia dan dalam bahasa apa dukungan tersebut diberikan. Dokumentasi yang lengkap dan komunitas pengguna yang aktif sangat membantu saat menghadapi masalah. Ketersediaan mitra konsultan lokal juga menjadi nilai tambah. Pertimbangkan pula ketersediaan tenaga kerja yang menguasai platform tersebut di pasar Indonesia. Platform yang populer biasanya lebih mudah dicari tenaga ahlinya.

**Portabilitas dan strategi keluar.** Pikirkan bagaimana cara berpindah jika suatu saat penyedia tidak lagi sesuai. Gunakan format data yang terbuka dan teknologi yang tidak terikat pada satu penyedia jika memungkinkan. Pastikan Anda bisa mengekspor data dengan mudah. Perhatikan klausul kontrak tentang penghentian layanan dan pengembalian data. Strategi keluar yang jelas memberi Anda posisi tawar yang lebih baik.

## Strategi Migrasi ke Cloud

Memindahkan sistem yang sudah berjalan ke cloud disebut migrasi cloud. Proses ini bisa sederhana untuk aplikasi kecil, tetapi bisa sangat rumit untuk sistem besar. Para praktisi mengenal beberapa strategi migrasi yang sering diringkas dengan istilah "6R". Setiap strategi memiliki tingkat usaha dan manfaat yang berbeda. Organisasi biasanya menggunakan kombinasi beberapa strategi untuk aplikasi yang berbeda.

**Rehost.** Strategi ini memindahkan aplikasi ke cloud apa adanya, tanpa perubahan berarti. Pendekatan ini sering disebut *lift and shift*. Prosesnya relatif cepat dan risikonya rendah. Namun, aplikasi belum memanfaatkan keunggulan cloud secara optimal. Strategi ini cocok sebagai langkah awal ketika organisasi perlu bermigrasi dengan cepat.

**Replatform.** Strategi ini melakukan sedikit penyesuaian agar aplikasi lebih cocok dengan lingkungan cloud. Contohnya adalah mengganti basis data yang dikelola sendiri dengan layanan basis data terkelola. Arsitektur inti aplikasi tidak berubah. Manfaatnya adalah berkurangnya beban pengelolaan tanpa harus menulis ulang aplikasi. Strategi ini menjadi jalan tengah antara kecepatan dan optimasi.

**Refactor.** Strategi ini merancang ulang aplikasi agar sepenuhnya memanfaatkan kemampuan cloud. Contohnya adalah memecah aplikasi besar menjadi layanan-layanan kecil atau menggunakan arsitektur serverless. Strategi ini membutuhkan usaha dan biaya paling besar. Namun, hasilnya adalah aplikasi yang lebih skalabel, tangguh, dan efisien. Strategi ini cocok untuk aplikasi inti yang menjadi keunggulan bisnis.

**Repurchase.** Strategi ini mengganti aplikasi lama dengan produk SaaS yang setara. Contohnya adalah mengganti sistem email internal dengan layanan email berbasis cloud. Organisasi tidak perlu lagi mengelola aplikasi tersebut. Tantangannya adalah memindahkan data dan menyesuaikan proses kerja dengan produk baru. Strategi ini sering dipilih untuk aplikasi yang bukan keunggulan inti bisnis.

**Retire dan Retain.** Migrasi juga menjadi kesempatan untuk meninjau seluruh portofolio aplikasi. Aplikasi yang sudah tidak digunakan sebaiknya dihentikan, yang disebut *retire*. Beberapa aplikasi mungkin belum siap atau tidak cocok dipindahkan, sehingga tetap dipertahankan di lokasi semula, yang disebut *retain*. Keputusan ini didasarkan pada nilai bisnis, kerumitan teknis, dan aturan yang berlaku. Tidak semua aplikasi harus dipindahkan ke cloud.

Apa pun strateginya, migrasi yang sukses membutuhkan perencanaan yang matang. Mulailah dengan inventarisasi aplikasi, data, dan ketergantungan antarsistem. Pilih aplikasi dengan risiko rendah sebagai proyek percontohan. Siapkan rencana pengujian dan rencana kembali jika migrasi bermasalah. Setelah migrasi selesai, lanjutkan dengan optimasi biaya dan kinerja secara berkelanjutan.

## Cara Mengendalikan Biaya Cloud

Pengendalian biaya adalah salah satu tantangan terbesar dalam penggunaan cloud. Karena sumber daya mudah dibuat, sumber daya juga mudah terlupakan. Disiplin pengelolaan biaya cloud dikenal dengan istilah FinOps. Praktik ini melibatkan kerja sama antara tim teknis, keuangan, dan bisnis. Berikut langkah-langkah praktis untuk menjaga biaya cloud tetap terkendali.

**Pasang anggaran dan peringatan.** Semua penyedia cloud besar menyediakan fitur anggaran dan peringatan biaya. Tetapkan batas anggaran bulanan dan atur peringatan ketika pemakaian mendekati batas tersebut. Peringatan ini membantu mendeteksi lonjakan biaya sejak dini. Banyak kasus tagihan membengkak sebenarnya bisa dicegah dengan langkah sederhana ini. Pastikan peringatan dikirim ke orang yang tepat dan ditindaklanjuti.

**Beri label pada setiap sumber daya.** Gunakan label atau *tag* untuk menandai pemilik, proyek, dan lingkungan setiap sumber daya. Dengan label, biaya bisa dikelompokkan dan dianalisis per tim atau per proyek. Anda juga bisa menemukan sumber daya yang tidak jelas pemiliknya. Sumber daya tanpa pemilik sering menjadi sumber pemborosan. Jadikan pemberian label sebagai aturan wajib.

**Sesuaikan ukuran sumber daya.** Banyak server berjalan dengan kapasitas jauh di atas kebutuhan sebenarnya. Pantau pemakaian prosesor dan memori secara berkala. Turunkan ukuran server yang pemakaiannya selalu rendah. Langkah ini disebut *right-sizing*. Penghematannya bisa cukup besar tanpa memengaruhi kinerja.

**Matikan sumber daya yang tidak digunakan.** Lingkungan pengembangan dan pengujian sering tidak digunakan di luar jam kerja. Matikan server-server tersebut secara otomatis pada malam hari dan akhir pekan. Hapus juga disk, cadangan, dan alamat IP yang sudah tidak terpakai. Tinjau sumber daya yang menganggur secara rutin. Pemborosan kecil yang dibiarkan lama-kelamaan menjadi besar.

**Manfaatkan diskon komitmen dan penskalaan otomatis.** Untuk beban kerja yang stabil dan dapat diprediksi, gunakan opsi diskon dengan komitmen pemakaian jangka panjang. Penyedia cloud biasanya memberikan potongan harga yang signifikan untuk komitmen tersebut. Untuk beban kerja yang naik turun, gunakan penskalaan otomatis agar kapasitas mengikuti permintaan. Untuk beban kerja yang bisa dihentikan sewaktu-waktu, pertimbangkan instans dengan harga lebih murah yang dapat ditarik kembali oleh penyedia. Kombinasi strategi ini membantu mendapatkan harga terbaik.

**Perhatikan biaya transfer data dan penyimpanan.** Biaya transfer data keluar dari cloud sering terlupakan dalam perencanaan. Gunakan CDN dan cache untuk mengurangi transfer data dari server utama. Untuk penyimpanan, pindahkan data yang jarang diakses ke kelas penyimpanan yang lebih murah. Atur kebijakan siklus hidup agar data lama dihapus atau diarsipkan secara otomatis. Langkah-langkah ini sering memberikan penghematan yang tidak terduga.

## Tren dan Masa Depan Cloud Computing

Cloud computing terus berkembang seiring kebutuhan baru di dunia teknologi. Beberapa tren sudah terlihat jelas dan diperkirakan akan semakin kuat. Memahami tren ini membantu organisasi merencanakan strategi teknologi jangka panjang. Tren-tren ini juga membuka peluang karier dan bisnis baru. Berikut beberapa tren penting dalam cloud computing.

**Cloud untuk kecerdasan buatan.** Pelatihan dan penggunaan model AI membutuhkan daya komputasi yang sangat besar. Penyedia cloud berlomba menyediakan GPU dan chip khusus AI dalam skala besar. Layanan model AI siap pakai juga semakin banyak ditawarkan melalui API. Bagi banyak organisasi, cloud adalah satu-satunya cara realistis untuk memanfaatkan AI tingkat lanjut. Tren ini diperkirakan akan terus mendorong pertumbuhan pasar cloud.

**Edge computing.** Edge computing memproses data di dekat sumbernya, bukan di pusat data yang jauh. Pendekatan ini penting untuk aplikasi yang membutuhkan respons sangat cepat, seperti kendaraan otonom dan otomasi pabrik. Edge computing juga mengurangi jumlah data yang harus dikirim ke cloud. Cloud dan edge tidak saling menggantikan, melainkan saling melengkapi. Hubungan keduanya sangat erat dengan perkembangan Internet of Things.

**Serverless dan platform pengembang.** Semakin banyak pengembang memilih layanan yang menyembunyikan detail infrastruktur. Serverless, basis data terkelola, dan platform penerapan otomatis membuat pengembangan aplikasi lebih cepat. Tim kecil bisa membangun aplikasi berskala besar tanpa tim infrastruktur khusus. Tren ini menggeser fokus dari mengelola server ke membangun fitur. Meski begitu, pemahaman dasar tentang infrastruktur tetap penting untuk membuat keputusan yang tepat.

**Kedaulatan data dan cloud berdaulat.** Banyak negara memperketat aturan tentang lokasi dan kendali atas data. Penyedia cloud merespons dengan menawarkan layanan yang memastikan data tetap berada dan dikelola di negara tertentu. Konsep ini dikenal sebagai *sovereign cloud*. Bagi Indonesia, tren ini sejalan dengan upaya memperkuat pelindungan data pribadi. Kehadiran lebih banyak pusat data di dalam negeri menjadi bagian dari tren tersebut.

**Keberlanjutan.** Konsumsi energi pusat data menjadi perhatian global, terutama dengan meningkatnya beban kerja AI. Penyedia cloud berinvestasi pada energi terbarukan dan teknologi pendingin yang lebih efisien. Beberapa penyedia juga menyediakan alat untuk mengukur jejak karbon pemakaian cloud pelanggan. Organisasi mulai mempertimbangkan aspek lingkungan dalam memilih penyedia dan region. Efisiensi biaya dan efisiensi energi sering berjalan beriringan.

## Karier di Bidang Cloud Computing

Pertumbuhan cloud computing menciptakan permintaan tinggi terhadap tenaga ahli di bidang ini. Banyak perusahaan di Indonesia sedang bertransformasi digital dan membutuhkan talenta cloud. Peluang karier tersedia di perusahaan teknologi, perbankan, telekomunikasi, hingga instansi pemerintah. Bidang ini juga terbuka bagi mereka yang beralih dari peran IT tradisional. Berikut beberapa peran yang umum di bidang cloud.

**Cloud engineer** bertugas membangun dan mengelola infrastruktur cloud. **Cloud architect** merancang arsitektur sistem yang aman, skalabel, dan efisien biaya. **DevOps engineer** dan **site reliability engineer** fokus pada otomatisasi, penerapan aplikasi, dan keandalan sistem. **Cloud security engineer** memastikan lingkungan cloud terlindungi dari ancaman. Ada juga peran yang berfokus pada data, seperti **data engineer**, yang membangun alur pemrosesan data di cloud.

Untuk memulai, pelajari dasar-dasar jaringan komputer, sistem operasi Linux, dan konsep keamanan. Setelah itu, pilih satu platform cloud dan pelajari layanan intinya. Penyedia cloud besar menawarkan materi belajar gratis dan program sertifikasi bertingkat. Sertifikasi tingkat dasar dapat menjadi titik awal yang baik untuk menunjukkan pemahaman Anda. Namun, pengalaman praktis melalui proyek nyata tetap menjadi nilai yang paling dihargai oleh perusahaan.

## FAQ Cloud Computing

### Apa yang dimaksud dengan cloud computing?

Cloud computing adalah penyediaan sumber daya komputasi seperti server, penyimpanan, dan perangkat lunak melalui internet sesuai permintaan. Pengguna tidak perlu membeli perangkat keras sendiri dan cukup membayar sesuai pemakaian. Layanan dapat diakses dari mana saja selama ada koneksi internet.

### Apa perbedaan IaaS, PaaS, dan SaaS?

IaaS menyediakan infrastruktur dasar seperti server virtual dan penyimpanan, sedangkan pengguna mengelola sistem operasi dan aplikasi. PaaS menyediakan platform siap pakai sehingga pengguna cukup fokus pada kode aplikasi. SaaS menyediakan aplikasi jadi yang langsung bisa digunakan, seperti email dan aplikasi perkantoran daring.

### Apakah data di cloud aman?

Penyedia cloud besar memiliki keamanan infrastruktur yang sangat baik. Namun, keamanan data juga bergantung pada cara pengguna mengatur akses, kata sandi, dan konfigurasi layanan. Banyak insiden kebocoran terjadi akibat kesalahan konfigurasi dari sisi pengguna.

### Apa contoh cloud computing yang sering digunakan?

Contoh yang paling umum adalah Google Drive, Gmail, Microsoft 365, layanan streaming, dan aplikasi belanja daring. Website dan aplikasi bisnis juga banyak dijalankan di platform cloud seperti AWS, Google Cloud, dan Azure. Asisten AI umumnya juga diproses di infrastruktur cloud.

### Apakah UMKM perlu menggunakan cloud computing?

UMKM bisa mendapatkan banyak manfaat dari cloud, terutama melalui layanan SaaS seperti aplikasi kasir, akuntansi, dan penyimpanan file. Biayanya terjangkau dan tidak memerlukan tim teknis khusus. Mulailah dari kebutuhan yang paling mendesak dan pilih layanan yang mudah digunakan.

### Apa itu hybrid cloud?

Hybrid cloud adalah gabungan antara public cloud dengan private cloud atau infrastruktur lokal yang saling terhubung. Model ini memungkinkan organisasi menyimpan data sensitif di lingkungan privat sambil memanfaatkan skalabilitas public cloud. Hybrid cloud banyak digunakan oleh perusahaan besar dan lembaga dengan aturan data yang ketat.

## Kesimpulan

Cloud computing adalah model penyediaan sumber daya komputasi melalui internet yang dapat diakses sesuai permintaan dan dibayar sesuai pemakaian. Teknologi ini dibangun di atas pusat data besar, virtualisasi, dan otomatisasi. Model layanannya meliputi IaaS, PaaS, SaaS, dan serverless, sedangkan model penerapannya meliputi public, private, hybrid, dan multi-cloud. Manfaat utamanya adalah efisiensi biaya, skalabilitas, kecepatan inovasi, kolaborasi, dan ketahanan sistem. Namun, cloud juga membawa tantangan berupa biaya yang sulit dikendalikan, ketergantungan pada penyedia, keamanan, dan kepatuhan regulasi.

Kunci keberhasilan menggunakan cloud adalah perencanaan yang matang dan pengelolaan yang disiplin. Pahami model tanggung jawab bersama, patuhi regulasi yang berlaku di Indonesia, dan kendalikan biaya sejak awal. Pilih penyedia berdasarkan kebutuhan nyata, bukan sekadar popularitas. Untuk melindungi data di cloud maupun di perangkat pribadi, pelajari praktik dasar di artikel keamanan siber. Jika tertarik dengan teknologi yang menghubungkan perangkat fisik ke cloud, lanjutkan dengan membaca artikel Internet of Things.
